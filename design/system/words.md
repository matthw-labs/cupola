# Words: the lexicon and the formats

The reference half of the brand book's *Words* ([README](README.md#words)): the one word for each state, the formats of dates, times, sizes and spans, what a requester reads, and the words of handing a device over. The voice itself (plain, warm, short) stays in the README.

The state words live once in the code, `StateWord` and `Lexicon` in `lib/core/status/lexicon.dart`, and `test/tool/brand_book_guard_test.dart` keeps this file and that one together: every word the code holds is here, and every word the table names is in the code.

## The lexicon

One word per state, the same on every screen. The tone follows the tone rule below; a word with no tone carries no state.

| Word | Tone | Means |
|---|---|---|
| `Answering` | green | The service replied to the last check. |
| `Did not answer` | red | Nothing replied at its address. **The only red words**, never contracted; say who and since when: `Radarr did not answer since 20:41`. A connection with an address away whose two addresses both went unanswered says so of both, `Radarr did not answer at home or away`, names them under it (`At home · nas.home.arpa:7878`, `Away · radarr.example.net`) and takes no time; when no service answered and one was asked at both, the Home and the Stack say `No service answered, at home or away`. A service's Overview says it once for the page, not once per section, naming the address it asked: `Radarr did not answer at nas.home.arpa:7878.` |
| `Timed out` · `Radarr was reached but did not reply in time` | amber | Something took the connection at its address and never replied: the host is there and the server is stuck. Not red (the network is not the cause) and not answering: the header says `2 timed out` beside `12 of 14 answering`. Equal ones are one sentence: `Radarr, Sonarr and 6 others were reached but did not reply in time.` |
| `Not set up` · `Set up Plex` | — | No address or key yet. The control stays tappable and names the service. |
| `Retry` | — | Send the same request again. Offered only where the same request can still succeed: never after a refused key, and never beside an `http://` address nothing was sent to. After a refused sign-in it stays, because a ban runs out. `Run again` is a different action: it re-runs a scheduled task. |
| `Radarr answered but refused the key` | amber | An answer that says no. A fault, with its remedy (`Paste the key again`). A service that takes a sign-in or a token says so: `qBittorrent answered but refused the sign-in` (`Sign in again`), `Plex answered but refused the token` (`Paste the token again`). |
| `qBittorrent answered but refused this address` | amber | The service refused the address Cupola connects through, before it checked any password: its host check, or a proxy's. Never the sign-in's words, never `Sign in again`. The fix is in the service's own settings, which Cupola cannot open, so there is no remedy button: the sentence names the setting, `If the password is right, add this address to Server domains in qBittorrent's Web UI settings, or turn off Host header validation there.`, and `Retry` follows it. |
| `Cloudflare Access answered instead of Radarr` | amber | Something in front of the service answered in its place, and the service never saw the request. Named for what it is, with the access it wants: `Radarr is behind Cloudflare Access. Cupola needs a service token to reach it.` (`Add a service token`); with a token sent and refused, `Cloudflare Access did not accept the service token` · `Add a Service Auth policy for it on radarr.example.com, or make a new token if it expired.` (`Check the token`); `A sign-in page answered instead of Radarr` · `Something in front of Radarr asks for a sign-in that Cupola cannot complete.` (`Add access`); `A password prompt answered instead of Radarr` · `Something in front of Radarr asks for a username and password.` (`Add the password`), or `The proxy did not accept the password` (`Check the password`). The state word names it too: `Behind Cloudflare Access`, `Service token not accepted`, `Behind a sign-in page`, `Behind a password prompt`, `Password not accepted`. Never `Refused the key`: the key never reached the service. No `Retry`: the same request meets the same gateway. |
| `Access` · `None` · `Cloudflare Access` · `Password` · `Custom headers` | — | What a connection presents to a gateway in front of its service, on every request it makes (the API, the artwork, the WebSocket, the background search): the row under the credential in the connection's form, and in the first-run walk's step once a gateway's remedy asks for it (`Add a service token`, `Add the password`, `Add access`), so the fix is made before any connection is saved. Its fields are labelled and its secrets hidden with `Paste`: `Client ID` · `Client secret`, under the line `On Cloudflare: create a service token, then add a Service Auth policy for it to this application.`; `Proxy username` · `Proxy password`; `Header name` · `Header value` (`Add a header`, `Remove header`). The connection test of a service token says what Access did with it: `Access let the token through and Radarr answered.` · `Access did not accept the token: add a Service Auth policy for it on radarr.example.com.` · `Nothing reached Access.`; after one passes, to the connections the same Access team turned away, `Use the same token for Sonarr and Seerr?` (`Use it`, then `Saved the token for Sonarr and Seerr`), the team asked of the address once without the token when no failure of its own named it; on the first run, a later step the same team turned away takes the token as its remedy, `Use Radarr's token`, which fills the row and tests again. The app settles a clash instead of reporting one: no `Password` where the service signs in with Authorization itself (`Nginx Proxy Manager signs in with its own Authorization header, so a proxy password cannot travel with it.`, the same for NZBGet and Transmission); a custom header named like the credential's, `Cupola already sends Radarr's key. Move it to the API key field?` (`Move it`); one the transport or the service owns, `Cupola sets this header itself`. A gateway's remedy opens the form on this row with the choice it wants; on the first run it opens the row in the step, never a form for a connection that is not saved yet. An address typed with `user:password@` is accepted in both and taken off on test or save. |
| `Radarr is not at this address` | amber | Something answered, and it is not the service: the probe checks who answered as well as that something did. Its sentence names who: `Sonarr answered at nas.home.arpa:7878, not Radarr` (a wrong port), `A web page answered at radarr.example.com instead of Radarr` (a proxy's page, a missing base path: the same words whichever request met it, the probe, the connection test or a library), or `Something answered at radarr.example.com, but it isn't Radarr` (an answer that is not the service's). The last two are followed, when the address has no path, by `If Radarr sits under a path, add it: https://radarr.example.com/radarr`. The remedy is `Check the address`. Home, the connection test and the library say the same words. `Radarr answered with something Cupola cannot read` is kept for a body that is not a page and does not decode. |
| `This is Emby` · `Set up Emby` | amber | The connection test of a form whose address another service of the stack answers (a Jellyfin form on an Emby's address; any pair): the headline names who answered, the cause line is kept (`Emby answered at nas.home.arpa:8096, not Jellyfin.`), and the remedy is the one amber fill under the panel, `Set up Emby`, at the 44pt target. It opens that service's form to add a connection (never an edit of one it already has) with the address filled in and the gateway access the test went through, unsaved; the key is never carried, and the address travels in the location, the access beside it in memory. The saved connection's header, Home and the library keep `Radarr is not at this address` and `Check the address`. |
| `—` | — | The source did not answer. A figure never reads `0` because a request failed. The dash is this placeholder and nothing else: copy never breaks a sentence with it (a full stop, a colon, a comma or ` · ` instead), and a range takes the en dash, `S2 E4–E5`. |
| `Needs you` | amber | The group of faults and approvals waiting for the operator: `3 faults · 2 requests`. |
| `Stuck` | amber | Nothing has arrived for a while: `Big Buck Bunny is stuck at 47%` · `nothing for 3 h`. |
| `Failed` | amber | It ended and cannot finish by itself. |
| `Stopped` | neutral | Someone stopped it on purpose. Not a fault, never "stuck". |
| `Paused` | neutral | A viewer's pause in a player: the session is still listed and holds its place (`Paused · Direct play`). Playback only: `Stopped` would say they ended it, and a download someone halted stays `Stopped`. |
| `Disk full` | amber | A usenet client paused itself because the next job does not fit where it downloads. Not `Stopped`, which someone chose: Home and the client's room read it from one rule. |
| `Blocklisted` | neutral | The operator put the title on Seerr's blocklist, so Seerr takes no request for it. A deliberate choice, not a fault. The state, never the action: `Blocklist and search` stays banned. |
| `Missing` · `Wanted` · `Cutoff unmet` · `Not aired` · `Not out yet` | neutral | The backlog: released and not on disk, still looked for, below its profile, not yet out. |
| `Waiting for approval` | blue | A request nobody has approved yet. |
| `Signed out` · `Signed out of Seerr` · `You were signed out` | blue | A Seerr account's session ended: unused for 30 days, signed out elsewhere, or the account removed. The person's own step, never a fault: the operator reads `Signed out of Seerr`, the requester `You were signed out` · `Sign in again to keep asking for movies and series.`, and the remedy is `Sign in again`, in ink rather than the fault's amber fill. No `Retry`: no request revives a session. Never `Refused the key`: no key was sent. |
| `Sign in with` · `API key` · `An account` | — | How a Seerr connection signs in: the instance's key, or a household member's own account. With an account: `Continue` (`Asking Seerr` while it reads the server), `Sign in to Seerr` (the server's own title), `Continue with Plex` · `Sign in with Jellyfin` · `Sign in with a code from Jellyfin` · `Sign in with Emby` · `Sign in with email`, and under them `Your password goes only to nas.home.arpa:5055. Cupola doesn't keep it.`; the form `Email` or `Username` · `Password` · `Show password` · `Sign in` (`Signing in`) · `Forgot your password?` · `Sign in another way`. Plex: `Finish signing in with Plex` · `Approve Cupola on the Plex page, then come back here.` · `Open the Plex page again` · `Cancel`. Quick Connect: the code, and `Open Jellyfin on a device where you're signed in, then enter this code under Quick Connect.` Signed in: `Signed in as Anna` · `Seerr · nas.home.arpa:5055` · `Sign out` (`Sign out of Seerr?` · `You'll need your password to sign in again.`, or `You'll sign in with Plex again.`). |
| `Seerr did not answer` · `This Seerr isn't set up yet` · `That email and password didn't work` | red · blue · amber | What a sign-in meets, each in the tone of what it is: nothing at the address (red, `Nothing replied at nas.home.arpa:5055 from this device.`, `Retry`, `Check the address`); `Something answered at nas.home.arpa:5055, but it isn't Seerr` (amber, `Check the address`); a server still in its first setup (blue, `Whoever runs it needs to finish setting it up before anyone can sign in.`, and nothing is ever sent to it: its first media-server sign-in would make the sender its admin); `This Seerr has sign-in turned off` (blue, `Use the API key`); `This address isn't encrypted` · `Anyone between you and the server could read your password.` (amber, `Use https` or `Continue anyway`); `That email and password didn't work` · `Check them and sign in again.`; `That username and password didn't work` · `Use the ones you watch Jellyfin with.`; `This account can't sign in here yet` · `Ask whoever runs the server to add you.` (`Sign in another way`); `The server could not reach Jellyfin` and `The server could not check your Plex account` · `It may be back in a moment.` (`Retry`); `This way of signing in was just turned off` (blue, the ways redrawn); `Plex did not answer` · `Cupola could not reach plex.tv from this device.` (red); `The Plex sign-in timed out` (blue, `Start again`); `The code expired` (blue, `Get a new code`). The password is gone from the form once sent, and none of these ever carries it. |
| `Seerr refused the request's security token` | amber | Seerr's CSRF protection refused a write twice, the second time with the token it had just handed out (the first refusal is answered by fetching a token and sending the write once more, unseen). `Nothing changed. Retry in a moment.` The state word is `Security token refused`. |
| `Coming up` | — | The next dated things. Films carry a date only; episodes a date and a time. |
| `in cinemas` · `on digital` · `on disc` | — | A film's three dated events, the same on the calendar and in Coming up: `Sprite Fright · on digital`. Not `digital release`, not `physical release`. |
| `Checked 2 h ago` · `Since you opened this` · `As of 20:53` | — | When a background check ran; a history that starts when the screen opened; a widget's snapshot. |
| `Only at home` · `Home only` · `Home and away` | neutral · — | `Only at home` is the state: away from home, a connection with no address away is not asked, so it never reads `Did not answer` and never stands in Needs you (`Lidarr only works at home.`, `7 of 7 answering · 6 only at home`; over the last drawing `Lidarr only works at home. As of 20:41.`); its remedy is `Add an address away`, in ink, which opens the connection's form on that empty field, focused. A service's Overview says it once for the page, not once per section, and the form says it above that field: `Lidarr has no address away, so Cupola reaches it only on your home Wi-Fi.` `Home only` and `Home and away` are the setup, on line two of a connection in Connections with the address in use (`Home and away · radarr.example.net`), said once any connection has an address away. |
| `Address at home` · `Address away · optional` · `Not checked from here` | — · blue | A connection's two addresses in its form, each with its own Access (folded to `Access · None · Change` while nothing stands in front of it). The test asks both: an address that did not answer while the other did reads blue `Not checked from here` (`Cupola tries it when the home address doesn't answer.`), saved anyway, since many routers cannot reach their own public address from inside; neither answering is red and names both (`Radarr did not answer at home or away.`). Connect says the same: `Address at home` with the default port under it and, on that line, `Add an address away` in ink, which opens the field under it with the keyboard on it; its Access row comes under it when a gateway asks; the test asks both and says each with its address (`At home · nas.home.arpa:7878`). An empty address at home is `Add the address at home` under the field, never `Server URL is required`. |
| `Cupola doesn't send your key over plain http across the internet.` · `Use https` | amber | An `http://` address off the local network, refused in both fields on every platform before anything is sent (`password` and `token` for the services that sign in with them); `Use https` is the one amber fill, and Save stays dimmed but tappable, leading to the refused field; in Connect, `Test connection` does the same. A tailnet address (100.64.0.0/10, `*.ts.net`) is encrypted by WireGuard and is never refused or warned about. |
| `serving` · `Spun down` | — / neutral | A Nginx Proxy Manager host whose configuration nginx loaded and answers on, never `Online`: nothing watches the service behind it (`radarr.lan:7878 · serving · TLS`); an Unraid disk asleep, which has no temperature. |
| `Monitored servers` · `Playing now` · `Violations` · `Most watched this week` | — | The sections of Tracearr's Overview, whose tabs are `Overview` · `Live` · `History` · `Users` · `Violations`. `Live` is the one place the Never list's word stays: the tab of streams in flight, named for what Tracearr calls it and not a state (Activity is already the tab of a media server's sessions). `Users`, not `People`: Tracearr's own word and the one Jellyfin's and Emby's tab says. A monitored server reads in the lexicon's words, never `Online` or `Down`: `Answering` green, `Did not answer Tracearr` red (Tracearr cannot reach it), `Refused Tracearr's token` amber with the one remedy only the owner can do, in Tracearr, `Fix it in Tracearr`; Tracearr's own `unknown` is a dash, never a state. `Most watched this week` is left out on a Tracearr that has no such read, never drawn empty. |
| `Low` · `Warning` · `High` | blue | A violation's severity in words, Tracearr's own, on a row that is blue whatever it says: a rule was broken, which is the person's to read, and nothing Cupola reaches has stopped working. Never a fault, never amber. An acknowledged one has been read and rests in neutral; a severity nobody could read is a dash. |
| `Unseen` · `Acknowledged` | blue · neutral | The violations nobody has looked at, where the Violations tab opens (`Unseen` · `All`), and the ones somebody has. The count of the unseen is a floor (`25+`) while another page follows: the API gives no total. |
| `Any severity` · `Show everyone` · `No violations match` | — | The Violations tab's filters: the severity (`Any severity` · `Low` · `Warning` · `High`, asked of the server beside `Unseen` · `All`), and the person a link narrows it to (`Only Anna's violations`, `Show everyone` to let go). A narrowed list that is empty says it is the filters, never `Nothing unseen`. |
| `Acknowledge` · `Dismiss` · `Sign in to Tracearr as the owner` | — | The owner's two writes on a violation. Without the owner's session both are dimmed, still tappable, and the tap leads to the connection's settings; `Dismiss` asks `Dismiss this violation?` (`Tracearr removes it and gives back the trust it cost Anna.`, `Dismiss violation` · `Keep it`: the first design said a bare `Dismiss`, which `test/core/theme/neutral_destructive_test.dart` refuses, since a confirm label is a verb and its object; the button that opens the dialog stays `Dismiss`). The answers: `Acknowledged`, `Dismissed`, `Signed out of Tracearr` (`Sign in again`), `Only the owner can acknowledge`, `Could not acknowledge this violation`, and for a Tracearr with no such route `This Tracearr cannot do that from Cupola.` (`Open in Tracearr`). |
| `What Tracearr did` · `What it saw` · `Only Tracearr shows what this rule saw` | amber for a failed action | A violation's page: the automatic actions with `Done` · `Skipped` · `Failed` (the one fault, amber, with what failed), and what the rule saw, typed for impossible travel (`First stream` · `Second stream` · `5,120 km apart` · `1 h 35 min between the two streams`) and concurrent streams (`4 streams at once` · `The limit is 2`); any other rule says only the line above and `Open in Tracearr`. |
| `3 violations to review` · `5+ violations to review` | blue | Needs you's line over the unseen violations of severity high (not faults, never amber, never a notification of Needs you); a floor when the list is longer than the page reads. The count in the section is its own group between the faults and the requests (`3 faults · 2 violations · 3 requests`). |
| `Streams now` · `Direct play` · `Direct stream` · `Transcode` | blue | Tracearr's rail (`Streams now` · `Today` · `Unseen` · `Servers`, `3 of 3`) and how a stream reaches the viewer, in Tracearr's three words, on a row blue while somebody watches. A stream with no decision says `Playing`, never a method it did not state. A viewer's pause is `Paused`. |
| `Stop this stream?` · `Message for Anna · optional` · `Stop stream` · `Keep playing` | neutral | Ending a stream from Live: a question, a word for the viewer that may stay empty (never claimed delivered: Tracearr relays it), a verb that names what happens and the other button that says the stream goes on. Not red, as every confirmation. What comes back is said once: `Stream stopped`, `That stream had already ended.`, or, from a Tracearr with no such route, `This Tracearr cannot stop streams.` (a fact about it, not a fault, and the control is gone for that connection). A refusal says `Tracearr refused (502)` and never the server's own sentence. |
| `Open title` · `Go to Anna` · `Source` · `Output` | — | The detail of a viewing, in Live and in History: source against output (video, audio, container), then bitrate, hardware, speed, subtitles, server, device, when, and how far or how it ended (`Watched`, `Stopped at 48%`). `Open title` only where the ids identify the title (a movie, a series; never an episode as its series), `Go to` only where one person has that name. |
| `Plex · through Tracearr` · `Tracearr did not answer.` · `What only Tracearr sees is not shown.` · `In Tracearr` · `Open this person in Tracearr` | blue · red for the silence | Tracearr inside the rest of Cupola. Now playing and Watching now are one list: a playback a media server and Tracearr both describe is one row, the server's (its Stop, its page), and Tracearr only adds to it; one only Tracearr sees (a server Cupola is not connected to) is appended with `Plex · through Tracearr`, like `Jellyfin · through Seerr`, first on its line, with no Stop, no Play and no Watch, and a tap goes to Tracearr's Live. The header names each server once, the through ones after the others. Tracearr alone is enough for the module to exist. Silent, the servers' own rows stay and one line says so, `Tracearr did not answer.` and what is gone, `What only Tracearr sees is not shown.`, red as any server that did not answer, amber when it refused the key. `In Tracearr` marks a Jellyfin or Emby Users row that leads to the person's page there (matched on the account's id on the server); a Plex session has no Users tab, so its Now playing row's disc and its card's `Open this person in Tracearr` lead there instead. Only where Tracearr is set up and knows the person: otherwise there is no mark and no door. |
| `Watched by` · `Watched by 3 · last 12 days ago` · `Nobody has watched it` | — | Who watched a title, from Tracearr, on the operator's Media page and one line in the removal sheet of a movie or a series (`Remove Big Buck Bunny from Radarr?`, under the sentence, in the secondary ink). A row per person, their accounts on every server added up: `4 plays · 100% · last 2 days ago`, a series first `7 episodes · 9 plays · 32% · last yesterday`; the day is counted in calendar days (`today` · `yesterday` · `12 days ago`, from two months on `on Tue 29 Sep`). Only when Tracearr answered for the title: a Tracearr that is not set up, did not answer or does not know the title draws nothing, because unknown is never `Nobody has watched it`. |
| `Anyone` · `Any server` · `Any type` · `Any time` · `Only watched` · `Clear` · `Include removed` | — | History's filters, each the server's and remembered per connection, and Users' toggle. Types: `Movies` · `Episodes` · `Tracks` · `TV` · `Photos` · `Trailers`; periods: `Today` · `Last 7 days` · `Last 30 days`. No library filter: Tracearr has none to offer, and a filter over the pages read would show an empty list while older pages held plenty. A day heading is `Today` · `Yesterday` · `Tue 6 Oct`, on this device's calendar. |

**A stuck download's remedies**, each for its own cause: `Try another download` (it can never finish: the arr drops this one, won't pick it again, and looks for another) · `Look for peers again` (someone has the whole file but nobody is reachable) · `Keep waiting` (hides the fault for 24 hours; it comes back if nothing has moved) · `Remove download` (stops it and deletes what arrived, behind a neutral confirmation; the title stays wanted).

**Never:** `Pending` · `Offline` · `Online` · `Connected` · `Unreachable` · `not answering` · `did not respond` · `Down` · `Not configured` · `Connect Seerr` · `Try again` · `Film` (the app says `movie`, as Radarr and Seerr do; `in cinemas` stays, it is Radarr's term) · `Couldn't` · `Failed to` (the app writes `Could not`, in a toast, a failure line and a notice alike) · `Hash copied to clipboard` (a copy says *Copied*, whatever it copied) · `Paused` (except a player's pause) · `Live` (as a state; Tracearr's tab is named `Live`, a place) · `Instantly` · `Please wait` · `Oops` · `Sorry` · `Error 401` · `Reannounce` · `Blocklist and search` · `Snooze` · a bare `Delete` · `0` for a source that did not answer · `0 °C` for a sleeping disk · an em dash between words (U+2014 as punctuation, as in `Saved`, dash, `Radarr`). A word from this list that still appears in the app is a defect to replace, not a precedent. The state words live once in the code (`StateWord` and `Lexicon` in `lib/core/status/lexicon.dart`; the failure words in the classification, `failureLabel` and `failureHeadline`), and `test/core/theme/lexicon_guard_test.dart` scans every string in `lib/` for this list, the dash between words included; its short allow-list names why each surviving word is not the banned state.

## Formats

Dates `Tue 29 Sep` (a year only when it is another year; `formatShortDate` in `lib/core/utils/date_format.dart`) · times 24 h, `21:00` · ages `12 min ago`, `2 h ago` · estimates `ready around 21:10`, `about 9 h left` · a span of time `48 s`, `12 min`, `2 h 30 min`, `3 d 4 h`, two units at most and never `12m` or `1h 5m` (one formatter, `formatTimeSpan` in `lib/core/utils/duration_format.dart`) · sizes in binary units labelled `KB`, `MB`, `GB` as the services' own screens show them, one decimal and whole from 100 up in a unit, bytes whole (`512 B`, `1.2 GB`, `152 GB`, `120 of 152 GB`, `31.2 of 43.6 TB`; one rule in `lib/core/utils/byte_format.dart`, held by `test/core/utils/byte_format_test.dart`) · speeds the same, `4.2 MB/s`, `120 MB/s`, `↓ 22.4 MB/s ↑ 1.1 MB/s` · percent glued to its figure, `62%` (`formatPercent` in `lib/core/utils/percent_format.dart`) · counts with a comma and "of" for a part, `1,240 albums`, `12 of 12 answering` · ranges with an en dash and no spaces, `S2 E6–E10` · episodes `S2 E3`, never padded, spelled in one place (`lib/core/utils/episode_code.dart`, held by `test/core/utils/episode_code_guard_test.dart`) · ratings each by its source, never averaged, `TMDB 6.6 · IMDb 6.7` · facts joined by a middle dot between spaces, `Cupola 1.0.0 · Apache-2.0`, the space before it a no-break one so a wrapped line ends with the dot and never starts with it (`dotSeparator` in `lib/core/utils/dot_separator.dart`, held by `test/core/utils/dot_separator_guard_test.dart`) · a path with an arrow, `Radarr → qBittorrent` · machine strings exactly as returned, in mono. Between a number and its unit symbol goes a no-break space (`unitSpace`, U+00A0; `withUnit` in `lib/core/utils/unit_space.dart` joins them), so `4.4 GB`, `4.2 MB/s`, `9 h` and `41 °C` never split (and `withUnit` puts a word joiner, U+2060, after the slash of `MB/s`, where a line could otherwise break), held by `test/core/utils/unit_space_guard_test.dart`, which also fails on a compact `12m`; a unit spelled out as a word in a sentence (`3 days`) is prose and breaks like prose. The percent sign is part of its figure and takes no space at all.

## The requester

A requester has a Seerr account and nothing else. Their screens say what will happen to a request, never how: `Waiting for approval` · `Downloading 62% · ready around 21:10` · `On its way` (Seerr cannot see the download) · `Finishing on the server` · `Ready to watch` · `On the server since Sat 12 Sep`. A title they asked for that was taken off the server reads `Removed from the server` · `You can ask for it again.`; one the owner blocked reads `Can't be requested` on its button, never the operator's `Blocklisted`. They never read a service name (Jellyfin, Plex and Emby excepted; they watch in them), a fault, or a figure they cannot act on; when the server does not answer they get one line, its time and `Retry`: `Can't reach the server since 20:41`, whatever the cause, the time being when the server first did not answer (`SilenceClock`: the first probe that did not, ended by any answer, in memory only), never when the line appeared; where the app did not see it stop (a cold start into a silent server, an answer that was an error) the line is `Can't reach the server` with no time, red only when nothing answered and amber otherwise, and `Retry` only where the same request can still succeed (`BriefFailureLine`, which every `AppErrorState` and `InlineErrorRetry` draws in the requester's app). An ended session is the one cause they can act on: `You were signed out` · `Sign in again to keep asking for movies and series.`, blue, `Sign in again`. **Today** a Seerr connection can sign in with a household member's own account from its form (`Sign in with` · `An account`), or from nothing on a first run through the Welcome's and the Home at zero's `I have a Seerr account` (`Sign in to ask for movies and series.`): `Where is your Seerr?` · `Seerr address` · `Whoever runs your server can tell you, or send you an invite.`, then the same ways in, and the app opens for whoever the account makes them, with no ring and no stack on the way. ## Another device

A device that has everything can hand it to a new one. The operator's Settings has `Set up another device` · `Copy everything to a new phone` (only with a connection to hand over), and the Welcome, the Home at zero and Settings' Connections have `Copy from another device`. The code on the sending screen is a QR and a `cupola://pair` link (`Copy link`, the way to a Mac, which has no camera). It holds where the other device fetches from (this device's address on the home network and a port the system picked for this one copy), the key that opens what it fetches, and when the code closes; it holds no connection and no secret of one. It works once, for two minutes, over the home network only: what is fetched is sealed with that key, and a code asked for anything else three times closes. What moves is every connection with its keys, passwords, tokens and the access a gateway in front of it asks for, and the certificate trusted at each address. What does not: a Seerr account's session, since a sign-in stays on the device it was made on (the new device signs in again as the same account: `Sign in to Seerr again here.`), Cupola's Plex identity, which names the install, how the app looks and what the Home shows, and a secret the sending device could not read from its own secure storage, which is named on both screens (`Radarr's key stays behind`, then `Radarr arrives without its key. Paste it here once it's added.`). The new device shows what Add would write before it writes anything: it only adds, a connection it already has (the same service at one of the same addresses) is left as it is, a certificate already trusted keeps its pin, and copying twice adds nothing. The link's key is never in a location, a log or a text field: the router takes the link off the address and holds it in memory, and a link pasted is gone from its field once read. A copy that did not arrive says why once, in the tone the cause has: red when the other device did not answer (`Cupola could not reach the other device`, with `Retry`), blue when the code ran out (`This code has expired`), amber when what arrived is wrong (`Cupola could not read what the other device sent`, `This came from a newer Cupola`, `This link isn't whole`), and the remedy is a new code, never the same request again where that cannot help.
